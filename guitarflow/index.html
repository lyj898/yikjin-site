How this was built

The engine. Each chord is defined as a set of MIDI note numbers — real guitar voicings across four strings. At playback time the audio engine converts those notes to frequencies, then schedules Web Audio API oscillator voices with a fast-attack, exponential-decay envelope through a low-pass filter. A short noise burst feeds a resonant bandpass filter tuned to each note's fundamental, adding the percussive "pluck" that gives a plucked-string character.

The strummer. Strum patterns are expressed as direction + timing maps. A down strum fires the chord's notes from lowest to highest, staggered by 18–30 ms depending on tempo. An up strum reverses the order. The fingerpick pattern follows a fixed arpeggio shape — bass, treble, middle, treble — spread across roughly 400 ms. Everything is scheduled against the AudioContext clock for sample-accurate timing.

The trade-off. Real guitar tone involves body resonance, string coupling, harmonic overtones that shift during decay, and the nonlinear response of a driven soundboard. This engine approximates the attack and harmonic structure with synthesis, but doesn't model any of those physical interactions. The result is a recognizable and playable guitar-like voice that works instantly in any browser — no samples to load, no libraries to ship.

What I'd improve. The 4-string voicings could become 6-string with proper muted-string modelling for open-position chords. Adding a convolution reverb with a small-room impulse response would make a surprisingly large difference in warmth. And a loop mode — where the progression cycles and the user can swap chords while it plays — would turn this from a player into a proper sketchpad.
